A warning can be ignored. A revert can't.

Most agent safety tools hand back a score or a warning, then leave the choice with the agent. That's useful advice right up until the agent is the thing that's been hijacked. BeforeCoin moves the check to where the money moves.

A check that advises

  1. The agent asks if a trade looks safe.
  2. A service answers with a verdict or a score.
  3. The agent decides what to do with that answer.
  4. A hijacked agent skips the question, and the trade still lands.

A check that's enforced

  1. The agent asks for clearance on the exact action.
  2. Verifiers each check it, and a quorum signs or doesn't.
  3. The pool's hook and the agent's wallet check those signatures.
  4. A hijacked agent skips the question, and the transaction reverts.

The limit of this: a hook only guards its own pool, so the agent's money has to sit in a BeforeCoin smart account. That wallet is the real enforcer. The hook is an opt-in safe pool.

From request to enforcement

Six steps, and the last one doesn't depend on any server being honest.

  1. The owner sets limits

    Size, price impact, tokens, pools and payees sit in the agent's ENS records. Verifiers read them from the chain, so no server can loosen them.

  2. The agent asks

    It sends the exact swap to POST /v1/clear/swap, and pays with x402 or an API key.

  3. Verifiers check separately

    Each reads the chain itself. Fixed rules decide, and missing or stale data always blocks. A model can explain or veto, and can never approve.

  4. A quorum signs

    One EIP-712 clearance, bound to the agent, pool, direction, amount, expiry and nonce. A refusal is no signature. A reduction is a smaller maxAmountIn.

  5. Big trades get a human and a second look

    Over the limit, the owner approves with World ID, for that one action. A Chainlink CRE workflow then re-derives limits, quorum and market and writes its finding on chain.

  6. The chain enforces

    The v4 hook reverts anything without a valid clearance. The smart account refuses other pools, direct transfers and uncleared payments.

What it doesn't do

  • It doesn't predict prices or say a trade is a good idea.
  • USD values come from the owner-approved pool's own price, so approving a pool is a trust decision.
  • Finding no admin functions in a token doesn't prove the token is safe.

Known limits
  • Payment budgets and used approvals live in verifier memory, so a restart forgets them. The swap spend cap is on chain and doesn't have this limit.
  • USD values come from the owner-approved pool's own price. An independent price oracle is the next step for a live network.
  • Attestations delivered through CRE's mock forwarder aren't trustworthy. Real use needs a deployed workflow and the real forwarder.
  • One agent per deployment for now, because verifiers read one resolver.
  • The dashboard's admin token sits on its local dev server. A hosted version needs real owner sign-in first.
  • An independent review found a critical bug: anyone could open a pool on the hook at an absurd price. It's fixed and tested.

Questions

More in the docs and the repo.

What happens if an agent never calls BeforeCoin?

Nothing moves. The agent's key can only act through its smart account, and that account refuses swaps without a valid clearance, refuses other pools and has no way to send tokens directly.

Can a model approve a trade?

No. Fixed rules decide. A model can explain a decision or veto one, and it can never turn a refusal into an approval. Text from the agent goes in a reason field that rules never read.

What if the verifiers are down or disagree?

Fewer signatures than the quorum means no clearance, so the action stays refused. Missing or stale data blocks too. The local stack needs two of three, and an owner can raise that in ENS but can't go below the contract's floor.

Who runs the verifiers?

Right now, whoever runs the stack. pnpm start launches all three on one machine, each with its own key and its own reads of the chain. Real independence comes from different people running them, and that hasn't happened yet.

Is a clearance reusable?

No. It lasts 90 seconds, works once and only for the account it names, the pool, the direction and up to the amount signed. A copy from another caller reverts.

Does it work on any Uniswap pool?

The hook guards pools opened on it, by approved creators. The owner lists the pools they trust in ENS, and the wallet refuses everything else. Exact-output swaps are refused, because a hook can't bound their input before the swap runs.

Can I use this with real money?

Not yet. It isn't deployed to a live network and the contracts haven't had an external audit. Try it on the local chain, where nothing needs real funds or keys.

How do I connect the MCP server?

Add it to your client as beforecoin, with CLEARANCE_API_URL and CLEARANCE_API_KEY set. It speaks stdio, so the client starts it for you. Its five tools check a swap, request an attestation, read a proof, scan a token and read a checkpoint. The docs have a config checked with Claude Code and Cursor.
